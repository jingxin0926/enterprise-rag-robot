# Agent 演进边界

## 当前结论

当前项目保留单 Agent、Multi-Agent、任务规划、记忆、Prompt 管理和 LLM 评测模块，作为系统化学习材料。它们当前的定位是“实验域”，不是已经完成生产验收的功能。

RAG 问答、异步文档入库和数据集评测是稳定主链路。Agent 模块会按真实业务入口、工具权限约束、调用审计和回归评测逐项升级，避免只会讲概念、没有可验证结果。

## 下一步的真实 Agent

第一项升级是实现“知识运营 Agent”，仅允许调用下列只读工具：

1. `search_knowledge`：检索并返回带来源的知识片段。
2. `get_document_status`：查询文档入库状态与失败原因。
3. `get_evaluation_summary`：查询最近一次评测的核心指标与趋势。

约束：工具参数使用 Pydantic 校验；每次调用记录操作人、参数摘要、耗时和结果；最大调用轮次固定；工具失败时回退为可解释响应；为每个工具调用场景增加回归用例。

## 面试表述

先说明业务问题，再说明为什么一个工作流足够。只有当任务确实存在可独立执行、可并行、上下文边界清晰且收益可度量的子目标时，才升级为 Multi-Agent。多智能体不是架构起点，而是单 Agent 工作流无法满足任务复杂度后的选择；但其状态机、路由、记忆和工具安全机制都要通过本项目逐一掌握。
